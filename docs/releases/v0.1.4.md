## 1. 这个版本能做什么

| 能力 | 说明 |
|---|---|
| 两级选择 | 一级列供应商（别名 + 模型数 + 「当前使用」徽章），二级只列该家模型 |
| 浏览与使用解耦 | 一级点哪家就浏览哪家，与「当前正在用哪家」无关 |
| 保留原搜索 | 一级跨全部供应商搜；二级只搜本家 |
| 思考强度 | 三级面板可改 reasoning effort；**按模型记住选择**，切走再切回不丢 |
| 当前项聚焦 | 打开时高亮当前模型（点的是当前供应商才聚焦，否则从顶部开始） |
| 键盘操作 | ↑↓ 移动、Enter 选中、Esc 逐级返回、Tab 回退、输入法 `isComposing` 保护 |
| 点外部关闭 | 弹层外任意位置按下即关闭 |
| 跟随窗口 | 最大化/还原/滚动时弹层重新定位，不漂移 |
| 主题一致 | 只用 `--dsw-alias-*` 令牌，亮/暗色自动适配 |
| 失败可诊断 | 服务不可用时按钮变红、可点开面板看完整错误并重试 |

## 2. 架构事实（改动前必须知道）

### 2.1 交付形态

**无构建步骤**。`client.js` 直接以 `window.__ModuleLoader__.load({ id, factory })` 交付，仓库里提交的就是运行产物。

- `factory(require)` 只能拿到 `react` / `react-dom`（浏览器模块表）
- **不能用相对路径 import**，不能 `require` 任何 `@deepseek-ai/dsh-client-*`
- Host 半 `index.js` 是空实现（本插件纯客户端）

### 2.2 接管的座位

```
conversation.input.model          ← 单例 slot，本插件抢占成为 winner
  └─ conversation.input.model.label   ← 子 slot，必须重新声明（规则 R2）
```

注册形态：

```js
ctx.inject(['slots','modelDirectories','sessions','remote','remote.session'], (scope) => {
  scope.slots.inject('conversation.input.model', () =>
    scope.slots.register({ name, locale: NS, children: {...}, inject: (sessionId) => props }, ModelPicker));
});
```

> ⚠️ **`remote` / `remote.session` 必须注入。** 内置 `ModelDirectoryResolver.directoryFor()`
> 内部会读 `this.ctx.remote.session`；Cordis 把服务面重绑到**调用方**上下文，
> 少注入就报 `cannot get property "remote" without inject`。这是 0.1.2 修的根因，勿回退。

### 2.3 数据来源

全部复用内置 `modelDirectories` 服务，不自建状态：

```js
models.directoryFor(sessionId)  // → { store, load(), select(selection) }
```

快照形状：

```js
{ status, groups: [{ id, name, models: [{ id, name, reasoning? }] }],
  current: { provider, model, reasoningEffort? },
  failures: [{ id, name, message }], pending, retainedEffort }
```

写回：`select({ provider, model, reasoningEffort? })` → `{ ok } | { ok: false, error }`，
错误码 `session/writer-held` 表示会话正在写入。

### 2.4 关键规则（M1 实测得出，违反会返工）

| 规则 | 内容 |
|---|---|
| **R1** | 判断 slot 归属**只看实际渲染**，不要信 `Slots.listSubTree` 的 `occupants`（永远只显示内置那一项） |
| **R2** | 抢占单例 slot 后**必须重新声明子 slot**，否则第三方注册全部消失 |
| **R3** | 每次改 `client.js` **都要重启桌面应用**才能验证（无热重载）；纯函数用 `node:vm` 单测以少重启 |

补充坑（0.1.2–0.1.4 踩到）：

- **Cordis 服务面是 Proxy，连 `typeof face.method` 都会抛** `cannot get property "x" without inject` → 能力探测逐个 try/catch
- **弹层在 body portal 里**，点击外部的包含性判断必须查 portal 节点
- **React effect 的依赖数组在渲染期求值**，把 `useEffect(..., [closeMenu])` 写在 `const closeMenu` 之前会抛 TDZ
- **`undefined` 是有效记忆值**（表示「供应商默认」），必须用 `Map.has()` 区分「记住默认」与「从未记住」
- **UI 状态不要从「当前生效值」推导**（浏览目标 ≠ 选中状态；窗口坐标必须持续跟随）

## 4. 交互规格（已实现）

### 4.1 层级

```
L1 供应商 →（点）→ L2 该家模型 →（点「思考强度」行）→ L3 强度列表
L3 Esc/Tab → L2；L2 Esc/Shift+Tab → L1；L1 Esc → 关闭（搜索有内容时先清搜索）
```

### 4.2 定位

`menuPos` 用 `position: fixed` + `getBoundingClientRect()` 计算；宽度
`clamp(288, 380, trigger 宽度)`；下方空间 < 320px 且上方更宽时向上展开。
打开期间监听 `resize` / `scroll`(capture) / `visualViewport resize`，
`requestAnimationFrame` 合并为每帧最多一次重算。

### 4.3 思考强度记忆

```
resolveEffort 优先级：
  同一模型且会话有值 → 会话值
  该模型有记忆值     → 记忆值（可能是 undefined = 供应商默认）
  否则               → model.reasoning.defaultEffort
```

写入时机：显式选强度 / 选择模型时记录实际提交值 / 会话生效值回灌。

### 5.3 失败时怎么拿信息

桌面端默认没有 DevTools。不可用状态的设计就是**诊断通道**：

1. 触发按钮变红，文案 `模型目录不可用：<完整错误>`
2. **按钮仍可点击**，点开弹层显示完整错误 + 堆栈前 3 行（可选中复制）+ 重试按钮
3. 连续重试仍失败会 `console.error` 一条完整记录

## 6. 安装 / 卸载 / 回滚

### 6.1 当前安装方式（link）

profile 侧已存在：

```jsonc
// ~/.dsh/profiles/desktop/package.json
"dependencies": { "@local/dsh-model-picker-2level": "link:D:/vibe_coding/dsh-plugin-develop" }
```

`~/.dsh/profiles/desktop/node_modules/@local/dsh-model-picker-2level` 是指向项目目录的软链，
所以**改代码只需重启应用**，不用重装。

### 6.2 安装 / 卸载

```bash
# 安装（开发期，本地目录）
dsh plugin --profile desktop add "D:/vibe_coding/dsh-plugin-develop"

# 或在会话里用 plugin_manager 工具
#   install_bundle target=D:\vibe_coding\dsh-plugin-develop

# 卸载
dsh plugin --profile desktop remove @local/dsh-model-picker-2level
```

### 6.3 卸载后如何确认已恢复内置

卸载并重启后，输入框左侧应显示内置样式（`供应商 / 模型` + 思考强度后缀），
点开是**单层长列表**（不是两级）。若仍见两级，说明 Loader patch 未生效，检查
`~/.dsh/profiles/desktop/cordis.patch.yml` 是否残留 `model-picker-2level` 行。

### 6.4 回滚到上一存档

```bash
cd D:/vibe_coding/dsh-plugin-develop
git checkout v0.1.4        # 回到本存档
# 若只需退版本号：改 package.json 的 version 后重启
```

## 7. 仓库外的一处配套改动（重要）

`~/.dsh/profiles/desktop/cordis.patch.yml` 里 `llm-pi-ai` 的 `maxTokens`
原先把**上下文窗口**当成了**输出上限**（最大 1048576），会被供应商拒绝或造成无谓长尾等待。

已统一收敛为 **32768**（= 宿主自身 `DEFAULT_MAX_TOKENS`），共 21 处：

| 供应商 | 方式 | 数量 |
|---|---|---|
| `zai-coding-cn` | `modelOverrides`（不替换目录模型列表） | 4 |
| `qiniu` | 模型条目 `maxTokens` | 6 |
| `lyrouter` | 模型条目 `maxTokens` | 11 |
| `kimi-api` | 模型条目 `maxTokens`（该 route 不在目录里，不能用 overrides） | 2 |

> 这是**用户环境配置**，不在本仓库内。若迁移到别的机器，需要另行处理。
> 字段语义：`maxTokens` → 线上 `max_completion_tokens` / `max_tokens`；
> `contextWindow` 才是输入窗口。
