## 结论

现有架构可以继续使用：插件通过客户端单例 Slot 接管选择器，模型目录、当前选择与写回沿用宿主服务。无需为了第一轮稳定性工作引入构建系统或运行时依赖。

主要风险集中在 React 组件生命周期、事件冒泡和失败恢复，而原有测试以纯函数与源码正则断言为主，无法发现这些问题。本轮增加真实 React DOM 交互测试，先用测试复现问题，再修复主要缺陷。自动化共 53 项通过；这不等同于完成真实 Harness 端到端验收。

## 已修复问题

| 优先级 | 问题与影响 | 处理 |
|---|---|---|
| P1 | 同一组件跨会话复用时，初始化保存的目录不会随 props 变化；选择可能提交给旧会话 | 注入 sessionId，以 sessionId 作为内部组件 key，隔离目录订阅、菜单与待完成请求 |
| P1 | 搜索框和菜单都处理 ArrowUp/ArrowDown，冒泡后一次按键移动两次 | 移除输入框重复处理，由菜单统一处理 |
| P1 | 菜单截获按钮 Enter，激活返回、重试或思考强度按钮时却选择高亮行 | 按钮保留原生 Enter 激活，搜索框 Enter 才选择高亮项 |
| P1 | 写回成功前就记忆强度；宿主拒绝或网络失败后，下次切回会恢复失败的选择 | 合并模型与强度提交路径，仅在成功后更新记忆 |
| P1 | 目录不可用时直接返回整块诊断内容，挤占输入区并绕过触发按钮；重试设置相同 null 值，不重启 effect | 诊断放入触发按钮打开的 portal；使用重试计数启动新一轮解析 |
| P2 | 旧选择请求完成后关闭后来重新打开的菜单 | 菜单轮次标记隔离完成回调，并在卸载后停止更新界面 |
| P2 | 仅用 state busy 防重复，重渲染前的连续点击可能重复提交 | 用 ref 同步互斥，保留 busy 作为界面状态 |
| P2 | 子代理会话显示整块目录错误，未按约定显示禁用按钮 | 注入 locked，保留禁用的紧凑触发按钮 |
| P2 | 全局 mousedown.preventDefault 阻止搜索框鼠标定位和诊断文本选择 | 只阻止按钮鼠标按下带走搜索焦点 |
| P2 | 强度页输入搜索后变成跨供应商模型搜索，Enter 可能切换模型 | 搜索限定在强度选项，补齐中英文提示与 aria-label |
| P2 | 另一个供应商含相同 model id 时，被误当成当前模型自动高亮 | 高亮同时比较 provider 与 model |
| P2 | 模型目录失去 reasoning 能力后，同模型选择仍可能携带旧强度 | 判断能力后再继承强度 |
| P2 | npm test 在本机 Node 24 下报 MODULE_NOT_FOUND；.npmrc 写成 JSON 产生无效配置警告 | 使用 node --test 默认发现，.npmrc 改为 INI |
| P2 | 校验脚本声称检查客户端可加载，实际只查字符串 | 使用 node:vm Script 解析语法，语法错误会使 validate 失败 |

另补上目录退避定时器的 effect 清理，避免卸载后残留定时任务。
