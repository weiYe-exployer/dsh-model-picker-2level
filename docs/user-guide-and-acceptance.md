# 两级模型选择器：用户说明与人工验收

适用范围：v0.1.5 基本功能定稿版。编写日期：2026-10-27。本文以当前 client.js 的实际实现为准；旧设计文档里的计划功能可能尚未实现。定稿记录见 [v0.1.5 存档](releases/v0.1.5.md)。

## 1. 当前验收进度

用户已反馈：真实 Harness 验收清单第 1、4 项完成；旧键位下的方向键、Enter、Esc、空格相关操作已测试成功。之后按用户确认的简化规则修改了键位，新规则的人工复测见第 3 节，不沿用旧空格验收结论。

用户后续反馈：第 2 项三项（2A、2B、2C）均验证通过；第 3 项两项（3A 断网恢复、3C 生成中尝试切换）均验证通过。结果来源为用户真实 Harness 手测；未提供的模型名称、请求字段、错误码与日志细节不作推断。

用户已进一步确认：简化后的键盘测试通过，K1–K6 登记为用户实测通过。尚未明确反馈：2D 旧操作完成、3B 部分目录失败、3D 目录不可用诊断和读屏。3C 的通过反馈不单独证明实际触发过 session/writer-held 错误码。

## 2. 当前用户功能

| 功能 | 操作与效果 |
|---|---|
| 查看当前模型 | 输入区按钮显示供应商 / 模型；有推理能力时，附带当前强度或默认值 |
| 打开选择器 | 点击模型按钮；按钮已获得键盘焦点时，按 Enter 打开 |
| 浏览供应商 | 打开后先显示供应商列表、模型数和当前使用标记；当前供应商自动高亮 |
| 浏览一家模型 | 点某供应商或在搜索框用 ↑↓ 高亮后 Enter；只展示这家的模型。单纯浏览不切换当前模型 |
| 选择模型 | 点击模型，或在搜索框用 ↑↓ 高亮后 Enter；成功后关闭菜单并更新按钮 |
| 全局搜索 | 在供应商首页输入关键词，搜索全部供应商下的模型；结果显示所属供应商 |
| 本家搜索 | 进入某供应商后再输入，只搜索这家的模型 |
| 模糊搜索 | 不区分大小写；支持连续子串及字符按顺序分散出现的匹配。连续命中优先，同分保持目录顺序 |
| 清空搜索 | 点 ×，或搜索非空时按 Esc；保留菜单，回到当前页未过滤的列表 |
| 调整思考强度 | 当前模型支持时，供应商首页下方出现“思考强度”；点击进入，再选一个级别 |
| 搜索强度 | 强度页搜索只过滤强度名称 / id，不会搜索模型 |
| 记忆强度 | 同一应用进程内，按供应商 + 模型记忆成功选择；切走再切回可恢复。不同会话共享这份偏好记忆，但各会话实际选中值分别保存 |
| 返回首页 | 模型页 / 强度页顶部返回按钮，或空搜索时 Esc |
| 关闭菜单 | 首页空搜索时 Esc、点击模型按钮、点击菜单外部，或成功提交选择 |
| 失败提示 | 切换失败时保留菜单显示错误；目录服务不可用时，按钮可打开完整诊断和重新解析入口 |
| 子代理会话 | 模型按钮禁用，不允许在此处切换 |

“当前选中”与“高亮”不同：当前选中是会话实际使用的值；高亮是下一次 Enter 可能操作的行。移动高亮不会改变会话。

“高亮”与“键盘焦点”也不同：打开后真正的键盘焦点通常在搜索框。Tab 可以把焦点移到按钮；焦点在按钮上时，Enter 激活那个按钮。

### 思考强度的边界

- 只有目录声明支持推理的当前模型才显示强度入口，可选档位由宿主目录提供。
- 当前同一模型已有显式强度时优先沿用；切回另一个模型时使用记忆值，否则使用目录默认值。
- 应用重启后进程内记忆丢失；当前会话本身保存的实际强度仍以宿主恢复结果为准。
- “供应商默认”选项只在目录没有 defaultEffort 时额外出现；并非所有模型都提供这一选项。
- 两个会话仍使用同一模型时，改变会话 A 的强度不应立即改掉 B 已保存的强度。但 B 主动切走该模型再切回时，可能采用共享偏好中的新值，这是当前行为。

## 3. 简化键盘规则与复测

### 当前实际键位

| 场景 | 按键 | 当前行为 |
|---|---|---|
| 菜单关闭，焦点在模型按钮 | Enter | 打开菜单，优先聚焦搜索框，并高亮当前供应商 |
| 菜单打开 | ↑ / ↓ | 高亮前一 / 后一行；到头会循环 |
| 焦点在搜索框 | Enter | 进入高亮供应商，或提交高亮模型 / 强度 |
| 焦点在具体按钮 | Enter | 激活这个按钮，例如返回、清空、重试、模型行 |
| 搜索框有内容 | Esc | 先清空搜索，菜单保持打开 |
| 模型页 / 强度页，搜索为空 | Esc | 直接返回供应商首页 |
| 供应商首页，搜索为空 | Esc | 关闭菜单，焦点回到模型按钮 |
| 任何页 | Tab / Shift+Tab | 无插件自定义动作，保留控件已有的浏览器原生焦点行为 |
| 搜索框内 | 空格 | 普通文字输入；并非“回到当前项”快捷键 |
| 插件按钮已获得焦点 | 空格 | 不激活；使用 Enter 确认 |
| 输入法正在组字 | Enter 等 | 插件不将组字确认当作选择快捷键 |

插件专用键位只有 ↑、↓、Enter、Esc。已删除旧的 Tab 返回首页和 ↓ 打开菜单行为；空格也不再激活插件按钮。Tab / Shift+Tab 没有新增处理逻辑或新的可聚焦控件。强度页与模型页分别从供应商首页进入，Esc 从任一页返回供应商首页。

当原生焦点移动离开菜单和模型按钮时，已有的失焦关闭行为仍可关闭菜单；这不等于返回上一级。插件没有实现额外的 Tab 焦点循环或焦点与高亮同步。

搜索框只要有文字（包括空格），Esc 就先清空，保持当前页；再按 Esc 才返回或关闭。鼠标操作保持原样。

### 新键位快速验收

| 编号 | 步骤 | 通过标准 |
|---|---|---|
| K1 | 菜单关闭，聚焦模型按钮，分别按 ↓、空格，最后按 Enter | ↓、空格均不打开；只有 Enter 打开 |
| K2 | 打开后用 ↑↓ 高亮供应商，Enter 进入；再高亮模型，Enter 确认 | 每次方向键只移动一行；选择成功后关闭并更新模型 |
| K3 | 模型页输入关键词 → 连续按 Esc | 第一次清空并留在模型页；第二次回供应商首页；第三次关闭 |
| K4 | 进入思考强度页，搜索、清空、返回并用 Enter 选择一次 | Esc 同样先清搜索再返回；只有确认选择才改变强度 |
| K5 | 模型页搜索框内按 Tab / Shift+Tab | 不触发返回、不主动清空搜索、不提交选择；只保留原生焦点行为，焦点离开时可按既有规则关闭菜单 |
| K6 | 搜索框输入含空格的文字；再给模型行或强度入口按钮焦点，按空格 | 搜索框可输入空格；按钮不被空格激活，Enter 仍可激活 |

上述新键位已有自动化回归覆盖；用户在修改后进一步确认真实 Harness 键盘测试通过，本表登记为用户实测通过。读屏仍独立追踪，不由键盘操作通过推断。

## 4. 第 2 项怎么验收：实际选择、请求与会话隔离

准备两个普通测试会话 A、B，以及两个能正常调用的模型 M1、M2。尽量选模型 id 不同的模型；有条件时分别来自不同供应商。再选一个支持至少两档强度的模型 R。可以让 R 与 M1 是同一模型。

使用简单消息“仅回复 OK。”即可，避免为验收启动工具任务。

### 2A. 模型切换与实际请求

1. 在会话 A 选择 M1，确认按钮更新；关掉再打开，检查 M1 对应的供应商有当前标记、模型有勾选。
2. 发送一条测试消息，等待完成，记录成功 / 失败。
3. 在 A 切到 M2，重复检查与发送。
4. 若宿主提供模型变更记录、请求详情或日志，检查这一轮实际提交的 provider / model；也可用供应商侧请求记录核对。

通过标准：界面、宿主保存的选择、实际请求目标相符，M1 和 M2 均能发送。**只看按钮变化只能证明显示更新；模型回答“我是谁”不能证明实际路由。** 没有请求记录时，写“界面与实际发送通过，请求字段未核验”，不要猜测。

### 2B. 思考强度与切回记忆

1. 在 A 选择 R → 打开首页的思考强度入口 → 选一个非默认档，例如 high；记录按钮显示。
2. 发送测试消息。如果有请求详情，确认宿主提交的是对应强度。不同供应商可能把强度映射成不同参数，以该路由的实际记录为准。
3. 切到 M2，再切回 R；检查强度恢复为刚才成功选择的值。
4. 换另一档，例如 low，重复切走 / 切回。

通过标准：成功选择的强度显示正确、请求参数在可观测时一致、同一进程内切回可恢复。**回答长短、响应速度与是否展示思考内容，都不能单独证明强度生效。**

### 2C. 两个会话隔离（本轮最重要）

1. 在 A 选择 M1，在 B 选择 M2。往返 A、B 各两次，检查各自按钮值。
2. 回 A，把 M1 改为 M2，再回 B；B 应保持原来的选择，没有出现额外模型变更。
3. 将 A、B 都设为 R：A 设 low、B 设 high。只在 A 改强度，再回 B，检查 B 已保存的 high 不变。此步骤不要在 B 主动切走再切回 R，以免混入共享偏好记忆。
4. 分别在 A、B 发送消息；可观测时核对请求所属会话及模型 / 强度。

通过标准：每次操作只改当前会话，切回后各自选择正确，请求没有发到另一会话的模型配置。

### 2D. 请求未结束时离开（可复现则测）

如果模型切换本身明显耗时：在 A 点击选择后立刻关闭菜单并重新打开，或切到 B，等待旧操作完成。

通过标准：旧操作可以在 A 生效，但不能关闭后来新开的菜单，不能改 B 的选择或给 B 显示 A 的错误。操作太快无法制造窗口时，标记“未触发，自动化已覆盖”，不必重复大量尝试。

## 5. 第 3 项怎么验收：失败与恢复

**先区分三个层次：**供应商 API 不可用可能只让消息发送失败；目录可能仍来自本地配置 / 缓存；选择动作也可能只是写入本地会话。因此，断网后还能列模型、还能切模型，不自动代表插件有问题。

### 3A. 断网与恢复（无需改配置，先做这一项）

1. 联网状态下打开普通测试会话，记录当前模型。
2. 断开网络，打开菜单，记录目录是否仍可浏览；尝试切换一次。
3. 发送一条测试消息，记录失败发生在“切换”还是“发消息”。
4. 恢复网络，关闭并重新打开菜单，然后再次选择并发送。

通过标准：插件不崩溃、不挤坏输入区、不显示错误的成功状态；宿主允许离线切换时可以成功保存。切换本身被拒绝时，菜单应保留并提示；仅发消息失败时，错误可能由宿主会话区显示。恢复后可以再次正常操作。

若断网没有触发目录失败，结果写“离线浏览 / 恢复通过；目录失败未触发”，不要把它记成目录失败测试通过。

### 3B. 某一家目录失败、其他家正常（条件项）

只在独立测试 profile 或可恢复的测试配置中做。保留正常供应商 P，另备一个测试供应商 Q。记录 Q 原配置，再通过该供应商已有的配置入口，将 Q 的目录访问配置临时设为不可用；不要改日常使用的密钥。重新加载目录，必要时按宿主规则重启测试实例。

观察：

- 是否出现带 Q 名称的加载失败信息。
- P 是否仍可浏览、选择和正常使用。
- 恢复 Q 原配置并重新加载后，Q 是否恢复。

当前菜单没有独立的“刷新全部目录”按钮；关闭再打开会请求加载，但是否强制跳过缓存由宿主决定。若 Q 的目录纯本地或被缓存，错误配置可能只影响发消息，无法触发目录失败，标记“未触发”。不要为了触发而删除整个 profile、破坏目录文件或暴露密钥。

通过标准：一个供应商失败不拖垮其他家，错误可辨认，修复配置后可恢复。失败家具体是否保留旧模型列表，以宿主快照为准。

### 3C. 会话正在写入 / writer-held（条件项）

1. 在测试会话发起一个稍长的普通响应，让它保持生成中。
2. 在同一会话打开菜单，尝试选择另一模型或另一档强度。
3. 若被宿主拒绝，检查菜单是否保留，是否提示“该会话正在写入，请稍后重试”。
4. 等当前响应完成后，再点击目标模型 / 强度；检查成功恢复。
5. 若失败的是强度切换，确认它没有取代之前成功保存的强度记忆。

**生成中不保证一定触发 writer-held。** 具体锁定时机由宿主决定；若宿主允许切换，只记录“生成中切换被允许，锁定错误未触发”。如有宿主日志，可核实错误码是否为 session/writer-held。不要把“没有出现错误”误判为错误分支已通过。

这里还有一个现有限制：**选择失败条里的“重试”目前只重新加载目录，不会自动重新提交刚才的选择。** 想再次尝试写回，需要重新点击目标模型 / 强度。请按此行为验收，并将是否易于理解作为产品反馈。

### 3D. 目录服务不可用诊断（条件项）

只有真实遇到“模型目录不可用”时再验收，不建议人为损坏宿主安装来制造。

1. 检查输入区仍是紧凑模型按钮，没有直接铺开大块错误。
2. 点按钮，检查诊断弹层中的完整错误能否选中复制。
3. 依赖服务恢复后，点诊断面板的“重试”，检查目录是否能恢复。

这里的“重试”会重新解析目录服务，**与 3C 的选择失败重试不是同一个动作**。未出现此状态时，标记“未触发，自动化已覆盖”。

状态用：通过 / 不通过 / 未触发 / 无法观察请求字段。没有触发错误时不需要强行打通过。

| 编号 | 结果 | 简要记录 |
|---|---|---|
| 2A 模型切换与实际请求 | 用户实测通过 | 用户确认第 2 项三项均通过；具体模型及请求字段观察方式未记录 |
| 2B 强度与记忆 | 用户实测通过 | 用户确认通过；具体模型、档位及请求字段未记录 |
| 2C 会话隔离 | 用户实测通过 | 用户确认通过 |
| 2D 旧操作完成 | 待测 | 是否制造出等待窗口；新菜单是否被误关闭 |
| 3A 断网与恢复 | 用户实测通过 | 用户确认第 3 项两项均通过；具体离线表现未记录 |
| 3B 部分目录失败 | 待测 | 哪家失败；其他家是否正常；恢复结果 |
| 3C 生成中尝试切换 / writer-held | 用户实测通过 | 生成中切换验收通过；是否实际触发锁定错误码未单独确认 |

若失败，附“所在会话 → 当前模型 → 操作 → 实际现象 → 预期”即可。错误文字或截图可以附上，但请遮盖密钥和私密会话内容。
